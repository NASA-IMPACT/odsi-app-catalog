# Decisions (ADRs)

## 1. Astro + Pagefind over Next.js / React SPA
Static content catalog with typed frontmatter and zero-backend search. Astro content
collections validate every entry at build (Zod); Pagefind gives full-text + faceted search by
indexing built HTML — no server, no Algolia. Ships ~zero JS. Rejected Next.js (SSR overkill) and
a Vite+React SPA (hand-rolled routing/MDX/search, ships a bundle).

## 2. Catalog references, never hosts
Each entry links out to the tool's real GitHub repo. The site is an index/front door, not a
mirror. Keeps it lightweight and avoids drift with upstream sources.

## 3. `limitations` is required (≥1), enforced at build
Product requirement: every entry must acknowledge at least one limitation/risk. Implemented as
`z.array(z.string().min(1)).min(1)` so an empty/missing list fails `astro build` and CI — an
enforced gate, not a review convention. Rendered in a prominent "⚠ Limitations & Risks" panel
and surfaced as a count on each card.

## 4. Search = Pagefind (full-text) + DOM (facets)
Type/tag filtering is pure DOM off card `data-*` attributes (always works, incl. dev). Free-text
uses the Pagefind JS API (build-only) with a substring fallback when `/pagefind/` is absent.
Only detail pages are indexed (`data-pagefind-body`), so results map to entries, not the grid.

## 5. Videos: external-first, small committed clips allowed
Real demos should be youtube/vimeo embeds (click-to-load facade, zero repo weight). Small
schematic clips (≤ ~5 MB) may be committed under `public/videos/`, generated by
`scripts/gen-demo-videos.sh` (ffmpeg). The seed clips are illustrative animations, not real
screen recordings. No Git LFS (finicky on Netlify).

## 6. Brand "NASA ODSI", host under `NASA-IMPACT`
No `NASA-ODSI` GitHub org exists / is accessible. ODSI is treated as the program inside the
`NASA-IMPACT` org. Visible text says "NASA ODSI"; repo URLs stay `NASA-IMPACT`.

## 7. Netlify continuous deployment — current state (interim)
- Site `odsi-app-catalog` created via the Netlify API and linked to the repo.
- Git clone works via a **read-only deploy key** on the repo.
- **main → production auto-deploy works** via a Netlify **build hook** + a GitHub **push
  webhook** (`github-push-main`).
- **PR Deploy Previews are NOT enabled.** A deploy-key/API git connection cannot produce
  per-PR previews — that requires the site's git connection to be made through the **Netlify
  GitHub App**.
