# Project Rules for AI Assistants — odsi-app-catalog

Static Astro 5 + Pagefind catalog of NASA ODSI apps/skills/references. It links out to each
tool's real repo; it never hosts the tool. Deployed on Netlify. Node 20. No React.

## Rules / constraints

- **Never make `limitations` optional.** The Zod schema in `src/content.config.ts` requires
  `limitations` to have ≥1 item; this deliberately fails the build for entries with no risk
  disclosed. It's a product requirement.
- **Every entry = one MDX file** in `src/content/catalog/`. Filename = slug = route. Add new
  entries there (or via `npm run new-entry`), not by editing components.
- **Keep `ENTRY_TYPES` in sync** between `src/content.config.ts` and `scripts/new-entry.mjs`.
- **Pagefind search is build-only.** Don't expect `/pagefind/` in `astro dev`. Verify search
  with `npm run build && npm run preview`. Keep the dynamic-import + `@vite-ignore` pattern in
  `CatalogGrid.astro` (a runtime-built path string) so Vite doesn't resolve it at build.
- **Only detail pages are Pagefind-indexed** (`data-pagefind-body` + `data-pagefind-filter`).
  Don't add `data-pagefind-body` to the index page.
- **Demo videos**: small committed clips only (≤ ~5 MB) under `public/videos/`, regenerated by
  `scripts/gen-demo-videos.sh` (ffmpeg). No Git LFS. Prefer external embeds for real demos.
- **Branding is "NASA ODSI"** but the GitHub org is `NASA-IMPACT`. Keep repo URLs pointing at
  `NASA-IMPACT`; keep visible text as "NASA ODSI".
- **Commits: no AI co-author trailers.** Human author only.

## Architecture (brief)

`index.astro` → `CatalogGrid` (search + type/tag chips; DOM filters + Pagefind full-text).
`catalog/[id].astro` → `EntryLayout` (Limitations panel, Developer's suggestion tip, VideoEmbed,
then MDX body). Schema fields live only in `src/content.config.ts`.
